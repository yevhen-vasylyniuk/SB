# SB — REST API для приватного дитячого садка

## 1. Мета проєкту

Створити REST API для управління приватним дитячим садком. Система повинна підтримувати роботу з користувачами, батьками, працівниками, дітьми, групами, кімнатами, заняттями, рахунками та платежами.

## 2. Обов'язкове технічне обмеження

**Увесь програмний код проєкту має бути в одному файлі `index.js`.**

У `index.js` розміщуються:
- налаштування Express;
- підключення та налаштування SQLite;
- створення таблиць і початкових даних;
- реєстрація та авторизація;
- JWT і middleware перевірки ролей;
- усі маршрути API;
- бізнес-логіка;
- перевірка вхідних даних;
- обробка помилок;
- запуск сервера.

Не створювати окремі файли `auth.js`, `database.js`, `routes.js`, `controllers.js`, `models.js` або інші файли з програмною логікою.

Допоміжні файли дозволені: `package.json`, `package-lock.json`, `.gitignore`, `README.md`, документація та файл змінних середовища `.env` (секрети не завантажувати на GitHub).

## 3. Технології

- Node.js
- Express
- SQLite через `better-sqlite3`
- `bcryptjs` для хешування паролів
- `jsonwebtoken` для JWT
- `dotenv` для конфігурації

## 5. Правила спільної роботи

1. Увесь програмний код має залишатися в `index.js`.
2. Перед реалізацією функцій узгоджувати назви таблиць, полів, маршрутів і формат відповідей.
3. Не редагувати одночасно один і той самий блок `index.js` без координації.
4. Передавати код для інтеграції з коротким описом призначення, залежностей і маршрутів.
5. Після інтеграції перевіряти запуск сервера та відповідні API-запити.
6. Не завантажувати `.env`, паролі, токени або локальну базу даних у GitHub.
7. Не виконувати `git push` у `main`, не узгодивши це з Team Lead.
8. Не перезаписувати чужі зміни й перед початком роботи синхронізувати свою гілку.

## 6. Критерії готовності функції

Функція вважається готовою, коли:
- реалізація відповідає погодженим вимогам;
- перевіряються обов'язкові поля та некоректні дані;
- налаштовані потрібні права доступу;
- повертаються відповідні HTTP-статуси;
- обробляються очікувані помилки;
- функцію перевірено тестовими запитами;
- код інтегровано в `index.js` без порушення роботи інших функцій.

## 7. Поточний стан проєкту

Початкова конфігурація Node.js-проєкту створена. Встановлено Express, better-sqlite3, bcryptjs, jsonwebtoken і dotenv. У `index.js` є початковий каркас сервера та маршрут `/api/health`.

Наступний етап — узгодити схему бази даних і вимоги, а потім послідовно реалізувати функції та інтегрувати їх у `index.js`.
