# Критерії приймання Kindergarten API

**Дата:** 11.11.2026
**Пов'язані документи:** `README.md` (вимоги замовника), `API_DOCUMENTATION.md` (опис API), `QA_REPORT.md` (результати перевірок)

Формат кожного критерію: **за умови** → **коли** → **тоді**. Кожен критерій перевіряється запитом у Postman або автотестом на чистій БД. Позначка `[ ]` ставиться при прийманні.

Ролі: `admin`, `manager`, `parent`, `teacher`; `none` означає запит без токена.

---

## 0. Загальні критерії (діють для кожної функції)

- [ ] **AC-0.1** Запит без токена до захищеного маршруту повертає `401` з `{ "error": "..." }`.
- [ ] **AC-0.2** Токен із підробленим підписом, неправильною схемою (не `Bearer`) або сміттєвим значенням повертає `401`.
- [ ] **AC-0.3** Валідний токен з недостатньою роллю повертає `403`.
- [ ] **AC-0.4** Усі помилки мають формат `{ "error": "<непорожній рядок>" }`.
- [ ] **AC-0.5** ID у шляху `abc`, `01`, `1.0`, `+1`, `1e2` дають `400`; неіснуючий `999999` дає `404`.
- [ ] **AC-0.6** Некоректний JSON у тілі дає `400` з повідомленням «Некоректний формат JSON».
- [ ] **AC-0.7** Неіснуючий маршрут дає `404` у форматі `{ error }`.
- [ ] **AC-0.8** `DELETE` успішно повертає `204` з порожнім тілом; `DELETE` доступний лише `admin`.
- [ ] **AC-0.9** Відповіді ніколи не містять `passwordHash`.
- [ ] **AC-0.10** SQL-запити параметризовані (`?`), дані запиту не склеюються в SQL.
- [ ] **AC-0.11** Запис, що використовується іншими (кімната в групі, група з дітьми, викладач у розкладі), не видаляється каскадно: відповідь `409`.

## 1. Запуск і середовище

- [ ] **AC-1.1** `npm ci`, `npm run setup`, `npm run dev` на чистому клоні запускають сервер без ручного редагування коду.
- [ ] **AC-1.2** Без `JWT_SECRET` (або коротшого за 32 символи) сервер не стартує, з зрозумілим повідомленням.
- [ ] **AC-1.3** Без `ADMIN_PASSWORD` (або коротшого за 12 символів) на порожній БД сервер не стартує.
- [ ] **AC-1.4** `npm run setup` не перезаписує існуючий `.env`.
- [ ] **AC-1.5** При першому запуску створюються 10 таблиць, користувач `admin` і 5 дисциплін; повторний запуск не дублює дані.
- [ ] **AC-1.6** `GET /health` і `GET /api/health` повертають `200` з `{ status: "ok", database: "connected" }` без токена.
- [ ] **AC-1.7** `.env` і `*.db` не потрапляють у Git (`.gitignore`).
- [ ] **AC-1.8** `npm run lint` і `npm run format:check` проходять без помилок.
- [ ] **AC-1.9** `npm test` завершується без падінь і не змінює локальну `kindergarten.db`.

## 2. Автентифікація та користувачі

### 2.1. Вхід

- [ ] **AC-2.1.1** Вхід `admin` з правильним паролем: `200`, у відповіді `token`, `tokenType = "Bearer"`, `expiresIn = 28800`, `user` без хеша.
- [ ] **AC-2.1.2** Payload JWT містить `userId` і `role`; строк дії 8 годин.
- [ ] **AC-2.1.3** Невірний пароль або невідомий логін: `401`.
- [ ] **AC-2.1.4** Порожнє тіло, логін з пробілів, відсутній пароль, тіло-масив: `400`.
- [ ] **AC-2.1.5** Токен видаленого користувача або користувача зі зміненою роллю відхиляється (`401`).

### 2.2. Створення акаунтів (`POST /users`)

- [ ] **AC-2.2.1** `admin` створює акаунт будь-якої ролі: `201`.
- [ ] **AC-2.2.2** `manager` створює `parent`: `201`; створює `admin` або `teacher`: `403`.
- [ ] **AC-2.2.3** `parent` без `parentId`: `400`; з неіснуючим `parentId`: `404`.
- [ ] **AC-2.2.4** `teacher` з `employeeId` працівника іншої посади: `400`.
- [ ] **AC-2.2.5** `admin`/`manager` з `parentId` або `employeeId`: `400`.
- [ ] **AC-2.2.6** Пароль коротший за 12 символів, логін із пробілом по краях, невідома роль, зайві поля: `400`.
- [ ] **AC-2.2.7** Дубль логіна: `409`.
- [ ] **AC-2.2.8** `parent` і `teacher` до `POST /users`: `403`.

### 2.3. Перегляд і видалення

- [ ] **AC-2.3.1** `GET /users` лише для `admin`: `200`, елементи мають рівно поля `id, login, role, parentId, employeeId`.
- [ ] **AC-2.3.2** `manager`/`parent` до `GET /users`: `403`.
- [ ] **AC-2.3.3** `DELETE /users/:id` для `admin`: `204`; після цього вхід видаленого акаунта дає `401`.
- [ ] **AC-2.3.4** `admin` видаляє власний акаунт: `409`.
- [ ] **AC-2.3.5** `manager` до `DELETE /users/:id`: `403`.

## 3. Батьки та працівники

### 3.1. Батьки

- [ ] **AC-3.1.1** `admin` і `manager` виконують `GET`, `POST`, `PATCH`; `parent` і `teacher` отримують `403`.
- [ ] **AC-3.1.2** `POST` без `fullName` або із зайвим полем: `400`.
- [ ] **AC-3.1.3** Телефон: `+380501110001` приймається; менше 10 або більше 15 цифр, літери: `400`.
- [ ] **AC-3.1.4** Email: `a@b.com` приймається; `abc`, `a@` або довший за 254 символи: `400`.
- [ ] **AC-3.1.5** Порожній рядок або `null` для `phone`/`email` приймається й зберігається як відсутнє значення; `PATCH` очищає поле.
- [ ] **AC-3.1.6** `PATCH` з порожнім тілом: `400`; неіснуючий ID: `404`.
- [ ] **AC-3.1.7** `DELETE` батька без дітей і акаунта (`admin`): `204`; з дітьми або акаунтом: `409`; `manager`: `403`.

### 3.2. Працівники

- [ ] **AC-3.2.1** `admin` і `manager` створюють працівників усіх чотирьох посад; невідома посада: `400`.
- [ ] **AC-3.2.2** Другий менеджер (створення або зміна посади): `409`.
- [ ] **AC-3.2.3** `salaryRate`: від'ємне, дробове або рядок: `400`.
- [ ] **AC-3.2.4** Зміна посади вихователя/помічника групи або викладача з дисципліною, розкладом чи акаунтом: `409`.
- [ ] **AC-3.2.5** `DELETE` працівника з прив'язками: `409`; без прив'язок (`admin`): `204`.

## 4. Кімнати та дисципліни

- [ ] **AC-4.1.1** `admin` і `manager` читають кімнати; `parent`/`teacher`: `403`.
- [ ] **AC-4.1.2** `POST /rooms` без `rent`: `201`, `rent = 50000`.
- [ ] **AC-4.1.3** `admin` створює й змінює кімнату з довільним `rent ≥ 0`: `201`/`200`.
- [ ] **AC-4.1.4** `manager` з полем `rent` у `POST` або `PATCH`: `403`.
- [ ] **AC-4.1.5** `manager` змінює `name`/`type` без `rent`: `200`, `rent` не змінюється.
- [ ] **AC-4.1.6** `rent < 0`, невірний `type`, невідоме поле в `PATCH`, порожній `PATCH`: `400`.
- [ ] **AC-4.1.7** Дубль назви: `409`.
- [ ] **AC-4.1.8** Базова кімната групи → `specialized`: `409`; зал дисципліни → `base`: `409`.
- [ ] **AC-4.1.9** `DELETE` кімнати групи, дисципліни або розкладу: `409`; вільної (`admin`): `204`.

### 4.2. Дисципліни

- [ ] **AC-4.2.1** Після старту є рівно 5 дисциплін без викладача й кімнати.
- [ ] **AC-4.2.2** `PATCH` з викладачем (`teacher`) і залом (`specialized`): `200`.
- [ ] **AC-4.2.3** Працівник не `teacher`: `409`; неіснуючий викладач або кімната: `404`; базова кімната: `409`.
- [ ] **AC-4.2.4** Дубль назви: `409`; `POST` без `name`, невідоме поле: `400`.
- [ ] **AC-4.2.5** `DELETE` дисципліни з розкладу: `409`; без розкладу (`admin`): `204`.

## 5. Групи

- [ ] **AC-5.1** `admin` і `manager` створюють і змінюють групи; `DELETE` лише `admin`.
- [ ] **AC-5.2** `ageCategory` поза 2–5, `capacity` поза 1–20, порожня назва: `400`.
- [ ] **AC-5.3** Нова група має `capacity = 20` за замовчуванням і `enrolled = 0`.
- [ ] **AC-5.4** Дубль назви: `409`. Ліміт 30 груп: 31-ша група дає `409`.
- [ ] **AC-5.5** Кімната: неіснуюча — `400`; `specialized` — `409`; зайнята іншою групою — `409`.
- [ ] **AC-5.6** Вихователь: не `educator` або неіснуючий — `400`; уже закріплений за іншою групою — `409`. Аналогічно для помічника (`assistant`).
- [ ] **AC-5.7** Вихователь і помічник не можуть бути одним працівником (`400`).
- [ ] **AC-5.8** `PATCH capacity` менше за кількість дітей: `409`; до 20: `200`.
- [ ] **AC-5.9** `PATCH ageCategory`, якщо в групі діти іншого віку: `409`.
- [ ] **AC-5.10** `DELETE` групи з дітьми або розкладом: `409`.
- [ ] **AC-5.11** Видимість `GET /groups`: `admin`/`manager` усі; `teacher` лише свої; `parent` лише групи своїх дітей і лише поля `id, name, ageCategory`.
- [ ] **AC-5.12** `GET /groups/:id` чужої групи для `parent` або `teacher`: `404`.
- [ ] **AC-5.13** `GET /groups/:id/children`: `admin`/`manager` — `200`; `parent`/`teacher` — `403`; неіснуюча група — `404`.

## 8. Розклад

- [ ] **AC-8.1.1** Без викладача й кімнати в усіх 5 дисциплін `POST /schedules/generate`: `409`.

- [ ] **AC-8.1.6** Повторна генерація замінює слоти без дублікатів.

### 8.2. Перегляд

- [ ] **AC-8.2.1** `admin`/`manager` бачать розклад будь-якої групи й будь-якого викладача.

- [ ] **AC-8.2.4** `teacher` бачить власний розклад; чужий: `403`. `parent` до розкладу викладача: `403`.
- [ ] **AC-8.2.5** Неіснуюча група/викладач: `404`; група без слотів: `404`; ID `abc`: `400`.

### 8.3. Перенесення слота (`PATCH /schedules/:id`)

- [ ] **AC-8.3.1** `admin`, `manager` переносять будь-який слот; `teacher` — лише власний; `parent`: `403`; без токена: `401`.
