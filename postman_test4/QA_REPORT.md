## Що перевірено та змінено у колекції

1. Актуалізовано 6 сценаріїв обмеження читання даних дітей для `teacher1`: `8.14`, `8.17`, `11.2`, `11.3`, `11.4`, `11.7`. Очікувана відповідь — `403 Forbidden`.
2. Актуалізовано `10.20`: для конфлікту одного заняття групи на день API повертає `409` та `type: group_limit`.
3. Додано розділ `18. Права менеджера та адміністратора на оренду кімнат`, 6 запитів:

| Запит | Сценарій | Очікувано і отримано |
|---|---|---|
| 18.1 | `manager`: POST /rooms із rent | 403 |
| 18.2 | `manager`: PATCH /rooms/:id із rent | 403 |
| 18.3 | `manager`: POST /rooms без rent | 201 (rent за замовчуванням) |
| 18.4 | `manager`: PATCH /rooms/:id без rent | 200 (rent не змінюється) |
| 18.5 | `admin`: POST /rooms із rent | 201 |
| 18.6 | `admin`: PATCH /rooms/:id із rent | 200 |

4. Виправлено використання `baseUrl` у вкладених Postman-скриптах: замість `pm.collectionVariables.get("baseUrl")` застосовано `pm.variables.get("baseUrl")` для врахування активного Environment. Це поліпшення внесене до експортованої колекції **після** фінального прогону; окремий повторний прогін цієї версії ще не проводився. Під час фінального прогону локальні Collection та Environment `baseUrl` були вирівняні на порт 3101.

## Запуск

1. Підготувати проєкт за README, ізольовану тестову базу; зупинити сервер перед `npm run db:reset`.
2. Імпортувати `Kindergarten_API_QA_postman_collection_full.json` і `kindergarten_qa_local.postman_environment.json` у Postman.
3. В Environment заповнити `adminPassword` **локально, не комітити**, а `baseUrl` встановити відповідно до свого порту (типово `http://localhost:3000`).
4. Запустити Collection Runner: усі запити за порядком від `00` до `18`, одна ітерація, без зупинки на першій помилці.
5. Для повторного повного прогону очистити тестову базу та перезапустити сервер.
